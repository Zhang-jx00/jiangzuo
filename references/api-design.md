# 分册：接口设计（HTTP/RPC）

> **何时读**：设计新接口、修改已有接口、前后端联调对不上字段时。
> **前置**：系统分层已定（design.md）。
> **产出**：接口契约落盘（templates/api-contract.md），前后端都按契约干活。

## 原则

接口是前后端之间的**合同**。合同先于施工：先写契约（路径、方法、请求、响应、错误），双方并行开发，联调才有依据。改已有接口视为破坏性变更，走 code-review.md 的破坏性检查。

## REST 设计规范

| 项 | 约定 | 例 |
|---|---|---|
| 资源用名词复数 | 不用动词 | `GET /orders` ✔、`GET /getOrders` ✘ |
| 动作放 HTTP 方法 | GET 查 / POST 建 / PUT/PATCH 改 / DELETE 删 | `DELETE /orders/123` |
| 非 CRUD 动作用子资源或动作后缀 | 语义清晰优先 | `POST /orders/123/cancel` |
| 层级 ≤2 层 | 过深改用查询参数 | `/users/5/orders` ✔ |
| 版本进路径或头 | 从第一版就定好 | `/api/v1/orders` |
| 命名风格全项目统一 | camelCase 或 snake_case 二选一 | 查项目现有接口照着写 |
| 时间一律 ISO 8601 带时区 | 不用时间戳字符串混搭 | `2026-10-05T12:30:00+08:00` |
| 金额用最小单位整数或字符串 decimal | 不用浮点 | `price_cents: 9900` |

## 响应结构（全项目统一一种）

```json
// 成功
{ "code": 0, "message": "ok", "data": { ... } }
// 失败
{ "code": 40010, "message": "优惠券已过期", "data": null }
```

- HTTP 状态码表达传输层语义（404 资源不存在、401 未登录、403 无权限、422 参数错误、500 服务器错误），业务码 `code` 表达业务语义，二者不混用。
- 错误码分段注册（如 40xxx 用户类、50xxx 系统类），建错误码表防止重复。
- **禁止**：所有响应都返回 200 把错误塞 body；把异常堆栈直接返回给前端。

## 分页 / 过滤 / 排序

- 分页：`?page=1&size=20` 或 `?cursor=xxx&limit=20`（大数据量用游标），响应带总数或下一页游标，**size 设上限**（如 ≤100）防拖库。
- 过滤：固定白名单参数（`?status=paid`），不做任意字段拼接查询。
- 排序：白名单字段（`?sort=created_at&order=desc`）。

## 认证与权限

- 认证方式（JWT / Session / API Key）沿用项目现状；没有现状就问用户。
- 每个接口明确标注：**公开 / 需登录 / 需特定权限**。权限模型用 RBAC 起步（用户-角色-权限）。
- 写接口必须校验"这个资源属于当前用户吗"（水平越权检查），服务端校验，前端隐藏不算数。
- 详见 security.md。

## 幂等与限流

- 涉及钱、库存、订单创建的 POST 接口支持幂等键（`Idempotency-Key` 头），重试不产生重复单。
- 公开接口和写接口考虑限流（按用户/IP），至少在方案里预留。

## 特殊接口模式

- **文件上传**：小文件 multipart 直传；大文件用"预签名 URL 直传对象存储"（服务端只发凭证不中转流量）。必须限制类型（白名单）、大小，落库的文件名服务端重新生成，不信任客户端原名。
- **文件下载**：流式输出或短时效签名 URL，禁止把大文件整体读进内存。
- **长任务**（导出、批量处理）：不要让 HTTP 请求挂几分钟。用 `202 Accepted + 任务 id`，`GET /jobs/{id}` 轮询状态（pending/running/done/failed + 进度），或 webhook 回调；任务结果有过期时间。
- **推送（WebSocket/SSE）**：只推事件通知，业务逻辑仍走 HTTP 接口；约定断线重连后的补拉机制（用最后收到的消息 id 增量拉取）。

## 成功 / 失败示例

**好**：新接口先写契约给用户和前端确认 → 双方按契约 mock 开发 → 联调时差异点记回契约。
**差**："后端写完前端对着响应字段猜"——每次字段改名都炸一遍。

## 常见错误

- 接口改了字段没通知调用方、没更新文档——破坏性变更。
- 列表接口没分页上限，一次拉全表。
- 布尔字段三种值（true/false/null）没约定含义。
- 业务错误码随手起号，重复冲突。
- 契约写完就过期，代码才是唯一真相——契约必须随代码一起改。
