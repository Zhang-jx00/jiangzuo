# 分册：全项目体检与漏洞审计

> **何时读**：用户要"整个项目找 bug / 安全审计 / 上线前扫一遍 / 接手仓库想摸清风险"；
> 或要求把风险量化（检出率、误报率、依赖优先级）；或要 SARIF 给 CI 用。
> **前置**：能读项目目录；已定级（这类任务通常是 L2/L3，跨全仓只读）。
> **产出**：`docs/jiangzuo/reports/` 下的审计报告（Markdown + JSON，可选 SARIF 2.1.0）
> ＋一份"复测点清单"＋按严重度排序的待办；**不改被扫项目的任何文件**。
> **CRITICAL：读完全册再动手；步骤按顺序执行，不得跳步。**

## 心法

工具负责**穷举与核验位置**，人负责**判断能不能被利用**。审计链的产物是"候选发现 + 证据链"，
不是"漏洞判决书"。把工具的 0 发现当成 0 风险，等于把安全外包给正则。

一条命令跑完整链（默认只读，缓存要显式开）：

```bash
python <技能目录>/scripts/audit_scan.py <项目目录> \
    --md 审计报告.md --json findings.json --sarif results.sarif
```

## 十步流程

1. **索引**（`audit_index.py`）：按 gitignore 语义出**可复现**文件清单（路径/字节/内容 sha1/语言），
   二进制与超限文件进 `skipped` 留痕。大仓先单独跑一次，后面几步复用同一份清单。
2. **侦察地图**（`audit_map.py`）：语言分布、入口、HTTP 路由、鉴权边界、依赖与锁文件、
   外部连接点。地图里 `auth=false` 只表示**本文件内未见鉴权标记**——全局中间件、网关、
   别处注册的装饰器它看不见。
3. **确定性粗筛**（scan 内部）：流式逐行匹配 sink/source，只记"哪个文件命中哪条规则"。
   注释行、三引号块、字符串字面量内部的命中**不算代码**（`ignore_strings` 规则另剥字面量）。
4. **语义深挖**：只对候选文件做邻近行核对（`unless_present`：白名单、净化库、属主条件在附近就放过）。
5. **数据流与可达性**（`audit_graph.py`）：source→赋值→拼接→sink 逐跳，跨函数跨文件传参，
   净化点断链并记账；从路由/入口 BFS 判可达。**不可达的保留但标"不可利用"**，不静默删。
6. **独立验证环节**：每条发现出报告前重新打开文件核五项——路径存在 / sink 证据仍匹配 /
   输入可控 / 净化未生效 / 可达。位置对不上**直接丢弃并计数**。
   这一层拦的是"报了个不存在的文件行号"，与 `code-review.md` 的自疑循环互补不替代。
7. **分级**：置信度（高/中/低）× 严重度（critical/high/medium/low/info）；
   依赖漏洞按**是否被实际调用**排序（包名与模块名差异走 `module_alias`）。
8. **报告**：Markdown（人读，含数据流与复测点）+ JSON（机器读）+ SARIF 2.1.0（CI/代码扫描平台）。
   同一问题按指纹去重；命中行**先脱敏再入报告**。
9. **人工确认**（不可外包）：越权、竞态、支付与业务规则类，工具只能给嫌疑点。
   逐条走 `security.md` 的两个问句：水平越权（换 id 能否拿别人数据）、
   垂直越权（普通角色能否调管理接口）。
10. **落盘与续扫**：报告进 `docs/jiangzuo/reports/`；确认要修的进任务计划，
    暂不修的进 `templates/tech-debt.md`；大仓用 `--cache DIR --incremental` 只重算变更文件
    及其调用链邻居（规则或解析器版本一变，缓存自动作废）。

## 规则治理

- 规则是数据：`scripts/audit-rules/*.json`，字段含 `kind`（taint/pattern/dependency/auth_gap）、
  `severity`、`cwe`/`owasp`、`sinks`/`sources`/`sanitizers`/`unless_present`、`fix`、`retest`。
- 加自己的规则：`--rules my-rules.json`（同 id 覆盖内置）；`python scripts/audit_rules.py --validate`
  会检查字段完备性与**每条正则能否编译**，坏规则当场退出码 1。
- 停用规则要有数据：`"enabled": false` + 在 `note` 里写实测误报数
  （`JZ-HORZ-001` 就是这么停的：夹具上 4/4 全误报）。加回用 `--enable-all`。
- 误报多时优先 `--ignore 'tests/fixtures/**'` 排除自造夹具，而不是急着删规则。
- **source 键要列全**：PHP 的 `$_REQUEST`、`$_COOKIE` 与 `$_GET` 一样可控，只写
  `$_GET|$_POST` 就漏整类流。DVWA 的命令注入最初是"守卫误报撞对了 sink"，
  收紧守卫后归零——那暴露的是 source 缺键，不是收紧过严。**误报被修掉后要回头看
  真阳有没有跟着掉**。
- 净化名单也是数据：`is_numeric/intval` 对命令注入是有效收敛（DVWA 官方修复档就是
  四段数值校验 + 逐段重组），但对 XSS 不是（`addslashes` 拦不住属性注入）。
  每条规则的净化只服务于它自己那一类。

## 验收怎么读（`evals/audit-acceptance.md`）

高危检出率、误报率、内存曲线、增量==全量都有分母，且必须同时看两节：
**含漏洞语料上的检出率**，和**干净仓库上的误报条数**。只看前者会高估自己——
本链第一版在自家仓库上报了 14 条发现，全是误报，修完字符串/注释屏蔽才归零。
语料由本仓库作者编写，"100% / 0%" 带出题人偏置，其证明力限于"类别可检出、安全写法可区分"。

出题人偏置从 v0.30 起有了外部对照：flask / requests / DVWA 三仓逐条人工判定。
结论要照着念，别只念好看的半边——**靶场侧精度达标（≈3/49），干净库侧不达标
（flask 13/13、requests 4/4 全是不可行动噪声）**，所以"误报率 ≤10%"这条验收
在真实第三方仓库上**仍未通过**。噪声集中在三类：测试/夹具路径下的能力型发现、
CLI 打到 stderr 的堆栈（不是 HTTP 响应）、库实现了某个危险选项（`CERT_NONE`）本身不是漏洞。

## 仓库角色与范围（先判角色再读结论）

- `repo_role()` 判 `library` / `app`：只有"没有路由 **且** 没有启动入口 **且** 有打包清单
  **且** docs/examples 之外没有真实页面文件"才算库。少一个条件都会把过程式 PHP 的
  应用判成库——DVWA 实测被这样误判过，**7 条真漏洞被当不适用吃掉**。
- 规则侧用 `scope: "app"` 声明"这条只在应用仓库算数"（调试开关、会话 cookie、
  错误回显、CSRF、异常信息）；库仓库里它们进「不适用」档，**既不算漏洞也不算已修**。
- `examples/`、`docs/`、`tests/` 下的**配置型**命中同样转不适用；
  **注入类（能力型）规则在这些路径仍然生效**——否则示例代码里的真写法就没人管了。
- 报告与 stdout 都会给「不适用 N 条」和逐条理由；只写"这条不重要"而说不出为什么的，
  不算判定，算静音。

## 性能与占用（这一层的成本从哪来）

链子是**分层的**，每层只干自己那件事，贵层由便宜层门控——这是它能扫大仓的原因：

| 层 | 干什么 | 成本口径 |
|---|---|---|
| 索引 | 一次打开算内容 sha1 ＋二进制探测 | 与文件数线性 |
| 地图 | 语言/入口/路由/依赖 | 与文件数线性（只扫清单与源码行） |
| 粗筛 | 按语言分桶匹配 sink/source | **不相关语言的模式一条都不碰；该语言无相关模式则文件都不打开** |
| 深挖 | 只对候选文件做邻近行核 | 与候选数相关 |
| 数据流 | 函数体＋跨文件传参 | **只解析「候选 ∪ 被候选调用的定义文件」** |
| 验证 | 重新打开文件核五项 | 与发现数相关 |

两条实测教训（写在这里免得后人重犯）：

1. **门控的 seed 必须是 sink 命中**。早期把 source 命中也当候选，
   而 `payload`、`body` 这类裸词几乎每份代码都有 → 1500 个文件全成候选，
   门控形同虚设。source 模式要带形态（`request.` / `req.` / `$_` / `params[`）。
2. **别拿本机计时当复杂度证据**。同一份代码单跑一遍全阶段统一慢 3 倍，
   其中一层我根本没改——那是环境噪声。所以回归锁的是**结构量**
   （`graph_parsed_files` 只随候选数变，仓库×4 它不变），不是毫秒数。
   毫秒预算只在 `bench.py` 里当人工参考。

```bash
python evals/audit-fixtures/bench.py --workdir ../eval-runs/bench --files 1500 --repeat 2
```

大仓建议：先 `audit_index.py` 出清单存盘，再 `audit_scan.py --index 清单.json` 复用；
续扫用 `--cache DIR --incremental`（只重算变更文件，规则或解析器一变整份缓存作废）。

## 误报怎么办：豁免是出口，不是静音键

业界三层（Semgrep `# nosemgrep`、Gitleaks `gitleaks:allow`、Trivy `.trivyignore`）我们都接了，
但**必须带理由，没写理由的豁免不生效**——否则误报只是从报告里消失，下次接手的人看不见：

```python
q = request.args["q"]      # jiangzuo:ignore JZ-SQLI-001 该服务只跑在内网批处理，无外部输入
```

```
# .jiangzuoignore（每行：路径模式 规则ID 理由）
tests/fixtures/** JZ-CMDI-001 夹具里的坏写法是故意的，用于回归检出能力
```

- 标记可以打在这条发现的**任一证据跳**上（污点流的发现行是 sink，人通常在 source 行注明理由）。
- 报告里单列「已豁免 N 条（含理由）」，并提示"另有 X 处没写理由的豁免未生效"。
- 某条规则反复被豁免 → 说明规则本身该收紧或该停用，走 `--validate` + `enabled:false`，
  不要靠豁免堆到看不见。

## 常见错误

- "扫描 0 发现，所以安全"——0 发现只说明这批规则没命中；逻辑漏洞、权限模型、竞态不在其列。
- 把 `auth=false` 直接写进报告当漏洞，不查全局中间件与网关（这是本项目实测的头号误报源）。
- 只贴报告不核证据：报告里的每条发现要能当场打开对应 `文件:行号` 看见那段代码。
- 把测试夹具、示例代码、文档里的"坏写法"当真实代码上报（先 `--ignore` 再谈结论）。
- 用 `--strict` 当 CI 门禁却不处理已知误报——门禁一旦常年红，就没人再看它。
  同一件事的反面：`bench.py` 的默认预算 3.0 ms/文件从有实测记录起就没达到过，
  常年 BENCH-FAIL 的闸等于没有闸；**预算要定在"当前能过、回退能拦"的位置**。
- 把守卫当数据入口：`if (isset($_POST['Submit']))` 里出现过 source ≠ 这条输入流到了 sink。
  内联兜底只在 source 与 sink **同一行**时成立（`os.system("ls " + request.args['d'])`）。
- 把字符串里的单词当变量读取：`prepare('… WHERE id = (:id)')` 的占位符名 `:id`
  撞上变量名 `id`，就能把官方修复档一路带成反射 XSS。只认各语言的显式内插语法。
- 静态图跟不动"变量路径 + 无括号"的 `include/require`（PHP 常见），于是真漏洞被标
  "不可利用"。这条链的兜底是把过程式 PHP 页面本身当入口根；
  读到"不可利用"时先问一句**是不是图没连上，而不是真的打不通**。
- 扫完就改：审计与修复必须分开交付（最小改动原则），修复走正常任务分级。
