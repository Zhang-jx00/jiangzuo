# 分册：安全清单

> **何时读**：涉及登录/注册/权限/支付/文件上传/外部输入/第三方调用的功能；上线前自查；用户提到"安全"时。
> **前置**：无。
> **产出**：安全检查通过的代码；发现的问题清单。
> **CRITICAL：读完全册再动手；步骤按顺序执行，不得跳步。**

## 心法

安全不是上线前的补丁，是每个阶段的钩子：**设计期**想权限模型，**编码期**做输入输出处理，**审查期**过清单。默认假设：所有外部输入都是恶意的，所有用户都会尝试访问别人的数据。

## 注入类

- **SQL 注入**：一律参数化查询/ORM，禁止字符串拼接 SQL。拼接表名/列名/排序字段时用白名单映射，因为参数化管不了它们。
- **命令注入**：避免拼 shell 命令；必须执行时用参数数组形式（不经过 shell 解释）。
- **路径穿越**：文件名/路径参数过滤 `..`、绝对路径，落地路径必须在限定目录内。

## 认证与会话

- 密码用 bcrypt/argon2 存哈希，**永远不存明文、不存 MD5/SHA1**。
- 登录失败有次数限制/验证码（防撞库）；会话有过期时间；登出要真正失效。
- JWT：校验签名和过期；敏感操作（改密、支付）重新验证密码；token 不放 URL。
- 改密后旧会话/token 失效策略要明确。

## 越权（最常被漏掉的一类）

每个需要登录的接口，写代码前先答两句：
- **水平越权**：用户 A 能否把 URL/请求里的 id 换成 B 的资源？→ 查询必须带属主条件（`WHERE id=? AND user_id=?`），服务端校验。
- **垂直越权**：普通用户能否调用管理员接口？→ 服务端校验角色/权限，前端隐藏菜单不算数。
- 对象级权限检查做成统一依赖/中间件，不靠每个接口自觉。

## XSS 与 CSRF

- 用户内容输出到页面时转义或用框架默认的安全渲染；禁 `innerHTML` 直接插用户输入。
- 富文本用白名单净化库（bleach、DOMPurify 类）。
- CSP 头按项目现状配置，至少禁止内联脚本执行不可信来源。
- 改数据的接口防 CSRF：SameSite Cookie / CSRF token（SPA + Bearer token 可豁免，但要确认）。
- CORS 按域名白名单配置，公开只读之外的接口**不用 `*`**；带凭证的请求必须显式列出来源。

## 敏感数据与密钥

- 密钥、连接串只进环境变量/密钥管理服务，**绝不进代码、绝不全量进 git**。
- preflight.py 的密钥扫描每次提交前都跑；发现已提交的密钥：**立即作废轮换**（改代码不删历史，泄露视同发生）。
- 日志脱敏：密码、token、手机号、身份证、银行卡不整串出现。
- 响应不泄露内部字段：哈希、内部标志、其他用户的字段。
- **审计日志**：敏感操作（改密、改权限、支付、删数据、导出大批数据）单独记录——谁、何时、对什么、结果——与普通业务日志分开存放，不可被业务代码篡改。
- 文件上传：类型白名单 + 大小限制 + 重命名存储 + 不放可执行目录 + 不信任用户给的文件名。

## 依赖与供应链

- 新依赖引入前过一眼：维护活跃度、周下载量、已知漏洞（`npm audit` / `pip-audit` / `cargo audit`）。
- 锁文件（lockfile）提交；定期升级；不引入"只为了一个小函数"的大依赖。

## 检查清单（改动涉及外部输入/权限时逐条过）

- [ ] 所有 SQL 参数化
- [ ] 每个资源接口过了水平越权问句
- [ ] 管理接口过了垂直越权问句
- [ ] 密码哈希算法合规
- [ ] 用户内容输出转义/净化
- [ ] 上传有类型/大小/存储路径限制
- [ ] 日志和响应无敏感值
- [ ] 无新增硬编码密钥（preflight.py 通过）
- [ ] 新依赖审计过
- [ ] 错误信息不向外部泄露堆栈/SQL/路径

## 常见错误

- "管理后台在二级域名下，不会有人发现"——权限校验照做。
- 只在渲染层转义，API 返回的 JSON 被 SPA 直接插入 DOM。
- 把 token 存 localStorage 且从不过期。
- 修复泄露的方式只是"改掉代码里的密钥"——旧密钥必须作废。
- 上传接口信任 `Content-Type` 头——它由客户端随意填。
