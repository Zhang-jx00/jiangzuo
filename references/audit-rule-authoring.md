# 分册：规则治理与引擎成本

> **何时读**：要加/改/停一条审计规则；规则"写了却没检出"要排查；扫描变慢或内存涨了；
> 动 `audit_rules.py` / `audit_scan.py` / `audit_graph.py` 任何一层之前。
> **前置**：手上有一份真实形状（要检出的那行代码 + 不该报的那行代码），不是凭类别名想象。
> **产出**：规则 JSON ＋ `--validate` 绿 ＋ 语料与靶场两侧数字 ＋ 变异校准记录（红/绿各一次）；
> **不改被扫项目**，只改本技能仓库。
> **CRITICAL：读完全册再动手；步骤按顺序执行，不得跳步。**

## 规则是数据，也是可执行代码

- 位置：`scripts/audit-rules/*.json`（现 3 个内置文件：注入类 / webapp 类 / 加密与客户端类）。
  字段：`kind`（taint/pattern/dependency/auth_gap）、`severity`、`cwe`/`owasp`、
  `sinks`/`sources`/`sanitizers`/`unless_present`、`fix`、`retest`、`scope`、`ignore_strings`。
- 每条规则带 `fix`（怎么改）与 `retest`（改完拿什么命令验），**没有这两样的规则不算合格**——
  报告里只能给出嫌疑点，给不出出口。
- 粗筛按**语言分桶**：一条规则的 pattern 只会喂给它声明的那些语言的文件；
  某语言一条相关模式都没有，那个文件**连打开都不打开**（这是能扫大仓的原因）。
- 桶还分**原文 / 掩码**两种：默认在"字符串字面量被剥掉"的掩码行上匹配；
  要认字符串内部的写法（如 PHP  heredoc 里的 JS、拼接进 HTML 的变量）必须自己判断该走哪一桶，
  **命中落在另一桶里时规则看起来就像"没生效"**。

## 四条"规则静默不生效"的实测坑（每条都有会红的判据）

1. **两份内置文件撞同一个 id = 后者整条遮蔽前者**。
   `load_rules()` 的"同 id 后者胜出"本来是给 `--add` 用户定制用的；v0.37 我自己新增规则时
   复用了已存在的 `JZ-CRYPTO-001`，按文件名排序被内置的另一条吃掉，**新规则一条都没跑**，
   表现出来却像"我正则写得不对所以没检出"——排查方向整个被带偏。
   判据：两份内置文件撞 id 直接判错并点名两个文件；用户覆盖内置仍放行（对照组锁住）。
2. **全局标志写在分支中间，只发 DeprecationWarning**。`A|(?i)B` 这种写法 Python 只是警告，
   `--validate` 照样 `RULES-OK`，换解释器版本就是 `SyntaxError`。
   判据：编译期告警升为判错。**跑闸门要连 stderr 一起看——警告不是"无所谓"，是"还没炸"。**
3. **正则复杂度是隐性功能缺陷**。一条 `[^;]*(?:A[^;]*<|<[^;]*A)` 失配时逐起点重扫＝O(n²)：
   600KB 行跑 106 秒；而扫描路径把单行截到 4096 字节，**本机永远看不出来**。
   判据：每个 pattern 都要吃两条 200K 对抗行且不超 500 ms（`TestAuditPatternCost`）。
   **一种形状不够**：锚点集中在末尾与锚点铺满全行是两种复杂度，各测一次才拦得住。
   对抗尺寸还要**小到"真是 O(n²) 也只几秒就红"**——Python 中断不了一次正在跑的正则，
   太大就把"锁"变成了"挂死"。
4. **source 键不全，整类流漏掉**。`$_REQUEST`/`$_COOKIE` 与 `$_GET` 一样可控，只写 GET|POST 就漏。
   DVWA 命令注入先被"守卫当入口"误报压掉、收紧后归零，暴露的是缺键不是收紧过严。
   判据：**误报修掉后要回头看真阳有没有跟着掉**（靶场侧拿模块名当分母复测）。

## 加一条规则的六步（顺序不许换）

1. **拿真实形状**：从被扫仓库里抄"要检出的那行"和"不该报的那行"，逐行读过。
   凭类别名编出来的形状，通常只能证明我会出题不能证明我会判卷。
2. **写反面半句**：每条新 sink 都配一条"这样写不该报"（GCM / 服务端下发令牌 / 普通拼接）。
   只测正例的锁，教出来的动作是"报得更多"。
3. **`--validate`**：字段完备性 + 每条正则能编译 + 控制字符哑弹检测 + 撞 id 检测。
4. **语料侧扩分母**：新规则要进 `gen_corpus.py` 的应检出与安全对照两组。
   真阳性撞上"答案清单没写"时，**补宽清单而不是压掉发现**（v0.37 的打包 JS 同时是动态执行）。
5. **靶场侧复测零回退**：`dvwa_coverage.py` 看主类别检出，flask / requests / 自扫看噪声没涨。
   **改了分母映射必须自陈**（我把 cryptography 从 001 扩到 001/002/003 就写在验收记录里）——
   不写清楚，"检出率涨了"就是自己改判卷标准。
6. **变异校准**：把这条规则的关键片段改掉，指定测试**必须红**；
   同时做一次"过度拦截"变异，反面那半句必须红。红错地方的校准算无效。

## 停用、豁免、范围：三个不同的出口

- `"enabled": false` + `note` 写实测误报数 = **数据停用**（`JZ-HORZ-001` 就是这么停的：夹具 4/4 全误报）。
  加回用 `--enable-all`。停用不等于删除，理由要留在库里。
- `scope: "app"` = 这条只在应用仓库算数；库仓库里它进「不适用」，**既不算漏洞也不算已修**。
- 行内 `# jiangzuo:ignore <规则ID> <理由>` 与 `.jiangzuoignore` 是**给人用的出口**，
  没写理由的豁免不生效；某条规则反复被豁免 → 该收紧或该停用，别靠豁免堆到看不见。

## 分层成本表（改哪层就知道动谁的预算）

| 层 | 干什么 | 成本口径 |
|---|---|---|
| 索引 | 一次打开算内容 sha1 ＋二进制探测 | 与文件数线性 |
| 地图 | 语言/入口/路由/依赖 | 与文件数线性（只扫清单与源码行） |
| 粗筛 | 按语言分桶匹配 sink/source | **不相关语言一条不碰；无相关模式则文件不打开** |
| 深挖 | 只对候选文件做邻近行核 | 与候选数相关 |
| 数据流 | 函数体＋跨文件传参 | **只解析「候选 ∪ 被候选调用的定义文件」** |
| 验证 | 重新打开文件核五项 | 与发现数相关 |

两条实测教训：

1. **门控的 seed 只能是 sink 命中**。把 source 命中也算进候选时，`payload`/`body` 这类裸词
   让 1500 个文件全成候选，门控形同虚设。source 模式必须带形态（`request.`/`req.`/`$_`/`params[`）。
2. **别拿本机计时当复杂度证据**。同一份代码单跑一遍全阶段统一慢 3 倍，而其中一层我根本没改。
   回归锁的是**结构量**（`graph_parsed_files` 只随候选数变，仓库×4 它不变），毫秒只在预算里当参考。
   性能优化还会**静默收窄能力面**：门控类改动必须配一条"能力还在"的测试（跨文件流、增量因果），
   不能只配"更快"的测试。

### 内存的真实形状（v0.39.1 复测，别再拿旧话糊）

- **门控路径**（真实仓库，多数文件没 sink）：×6.3 文件 → **×1.09 内存**，增量 0.38 KB/文件——已经是平的。
- **候选占满**（每个文件都含 sink，图层必须全解析）：严格线性，**15.4 KB/文件（峰值）/ 7.4 KB/文件（驻留）**。
  这不是 bug，是"为跨函数分析握住候选文本"的价钱；要不要付，先看目标仓库的候选占比。
- 图层**产物不带源码**：函数条目只有 `name/file/lang/start/end/params/calls`。
  这条有锁（带 `body`/`lines` 当场红）——一旦破防，每次交付的 JSON/SARIF 就会膨胀成仓库大小。
- **反面教训**：曾想加一条"驻留 KB/文件预算"锁，实测发现多存一份行元组只让驻留 7.4 → 9.0 KB/文件
  （字符串共享），阈值只能定在永远踩不到的位置 → **撤锁**，把结论写成上面那两个数字。
  一条永远绿的锁比没有锁更坏。

## 能力边界表（引擎做不到什么 · 为什么 · 代价）

**先分清"边界"与"缺陷"**：下面是**原理上做不到**的（静态分析拿不到那个证据）；
规则写得太宽（`preg_replace` 当动态代码执行、`error_reporting(E_ALL)` 当调试泄露、
`unless_present` 里一个 `csrf` 词就整条豁免）属于**可修的缺陷**，登记在 §11 待办，**不进这张表**。

**每条边界都必须有一条最小夹具钉住**（`tests/test_scripts.py` 的 `TestAuditCapabilityBoundaries`）：
否则引擎演进之后这张表会开始说谎——而说谎的边界表比没有边界表更坏。

| 边界 | 为什么做不到 | 代价（不修会怎样） | 实测证据（2026-10-21） |
|---|---|---|---|
| **缺失型判据**：暴力破解 / 验证码 / 速率限制 | 要证明"没有速率限制"，得看**中间件 / 网关 / WAF**——那些不在仓库里 ⇒ 静态扫描原理上拿不到这个证据 | 这类结论只能靠人工问句（WAF？`limit_req`？网关？）；**引擎不报 ≠ 安全** | DVWA `brute/`、`captcha/` 两个模块**零发现** |
| **净化点按 sink 上下文生效**（转义类净化） | 转义只在**引号内**有效、**数值上下文无效** ⇒ 要判对就得知道 sink 的 SQL 上下文（引号内 / 引号外 / 标识符）⇒ 需要 sink 级解析 | 一刀切把转义当净化 ⇒ 会把 `sqli_blind/source/medium.php`（**转义了但在引号外**）的**真阳性压掉** ⇒ 等于**拿真阳性换误报**，所以不做 | `JZ-SQLI-003` 的净化点 pattern 是 `\breal_escape_string\b`，**匹配不到** `mysqli_real_escape_string`（`_` 是单词字符 ⇒ 无词边界）⇒ 现在**转义处照报**。DVWA 三处形态完全一样、判定必须不同：`csrf/source/high.php:38→44`（引号内 ⇒ 硬误报）、`csrf/test_credentials.php:14→22`（引号内 ⇒ 硬误报）、`sqli_blind/source/medium.php:10→15`（引号外 ⇒ 真阳性） |
| **JS 里 `//` 的歧义**（注释 / 正则字面量 / 除法） | 单遍静态扫描分不清"正则里的 `//`"和"注释" ⇒ **两种做法都会漏报**：按代码处理会把真注释当代码，按注释处理会把正则后同行的代码吃掉 | 我们选"按注释处理"（除法更常见）⇒ **正则字面量同行之后的代码整段被漏掉**（真阳性丢失） | 夹具 `var re = /\/\//; var x = request.query['q']; eval(x);` ⇒ **0 条发现**；同一行去掉正则字面量 ⇒ **1 条**（真阳性） |
| **跨请求 / 存储型数据流**（存储型 XSS、跨文件会话） | 污点链只在**单文件 / 单函数 / 被调函数**内传播；"写进去 → 存下来 → 下一次请求读出来 → 渲染"要建模**存储介质**（DB / session / file）与请求边界 | 这类结论引擎**报不了**，只能人工沿数据流走一遍 | DVWA `xss_s/` 模块**零发现**；DVWA 主类别覆盖 **14/19**，5 个 MISS 里 2 个属此类 |
| **鉴权 / 越权**（"这个 action 有没有校验权限"） | 鉴权是**跨文件 / 跨请求**属性（路由 × 中间件 × 资源），单文件里看不到 ⇒ 现有 `JZ-HORZ-001` 形态**夹具 4/4 全误报** ⇒ 已**数据停用** | 鉴权类结论交人工问句（`security.md` 的属主问句），引擎不背这个锅 | `JZ-HORZ-001` `enabled:false`（`webapp.json`）；DVWA `bac/` 模块**零发现** |

**为什么这些"零发现"不是缺陷**：上面 5 条里有 3 条的 DVWA 模块**一条都没报**，
但那是**正确的**——那些洞要么需要跨请求视角、要么需要中间件视角。
**把"报不出来"直接当"漏报"去补规则，补出来的只会是误报**（`JZ-HORZ-001` 就是这么来的）。

## 常见错误

- 规则不加就没人管，加了没人验 → 一条没人校准的规则等于一条永远不会红的装饰。
- 只跑一次测试就说"锁有效"：新锁要先证明**它能红**（改坏源码/退回 HEAD 旧实现），再证明它绿。
- 把净化名单当万能：`addslashes` 拦不住属性注入，`intval` 对命令注入才是收敛——净化只服务自己那一类。
- 改引擎不改判据：动了分桶/遮蔽/掩码逻辑，配套的闸门（`--validate`、成本锁）要同步加一条会红的。
- **判据跟着解释器或平台换颜色**（v0.40.0 实拍，CI 红了 22 次才暴露）：索引路径锁把"本机绝对路径"的针
  归一化成**正斜杠**形式，而 Windows 上工具输出的是**反斜杠**形式——两边永远对不上，这条锁在本机从没成立过；
  另一条断言"全局标志写错位置"的**中文措辞**，而措辞是 CPython 给的（3.8 走 DeprecationWarning、
  3.11 走 re.error，换英文）——本机绿、Linux CI 红。规矩：**针按原样/绝对/真实/正斜杠四种形式各比一次**，
  并且只比机器可读产物；**给人看的消息由本项目生成**，解释器那两支只做兜底。
- 把"我改了 X"当成事实：批量文本替换必须打印命中数，改完 `grep` 目标行确认真值在里面。
- **待办也会过期**：两轮里各有一条"欠账"是旧结论当现状——"内存曲线不平坦待分块建图"（门控后已平，
  真实形状是候选占满时线性 15.4 KB/文件）、"静态 `require_once` 待精确建边"
  （函数调用早已按名字全仓解析，剩下的只有"被包含文件的模块级变量共享"一格）。
  **动一条待办之前，先用代码或测量复述它现在的真实范围**；范围窄了就改判为"需求驱动"，别做预防性工程。
- 报告里写死的数字没有闸：规则条数、入口行数、CHANGELOG 日期都复发过——
  **写进禁忌表的规矩要变成机器判据，否则照样复发**。
