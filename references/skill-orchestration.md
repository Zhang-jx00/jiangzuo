# 分册：技能协同（编排环境中的其他技能）

> **何时读**：任务中出现 SKILL.md 技能协同表里的情境；用户要求代码之外的交付物（演示、图表、正式文档、配图）；需要真实浏览器验证；想用其他技能时。
> **前置**：明确任务目标与交付物是什么。
> **产出**：经用户授权、经核验的多技能协作成果，记录在交付报告中。
> **CRITICAL：读完全册再动手；步骤按顺序执行，不得跳步。**

## 定位与三原则

将作监统领会各工种匠人：**你是总工程师，其他技能是分包商**。分包商手艺再好，接活要你交底、交货要你验收。

1. **适当才提**：任务真的需要才提议，不为炫技而编排。任务能用自己的方法完成且质量不差时，不打扰用户。
2. **获准才调**：默认每单都要用户点头；用户给过"常备授权"的情境除外。
3. **产出必验**：分包商的输出和子代理的输出一样，是"待验收的半成品"，不是成果。

## 协调协议五步（展开）

### 1. 盘点——知道现场有哪些匠人

- 可用技能清单以**当前环境实际提供**的为准（会话上下文中列出的技能），不假设"应该装了"。
- 不凭名字猜能力：拿不准某技能做什么、输入输出是什么，先读它的说明（其 SKILL.md 的 description 或文档），再决定是否提议。
- 把"环境里有什么装备"当摸底的一部分，L3 项目开始时顺手记进 project-profile（"可协同技能：……"）。

### 2. 提议——给用户选择题

话术模板（一次最多提 1-2 个最相关的，不轰炸）：

> 这个任务需要产出 ____。环境里有 ____ 技能，我建议用它来做 ____，因为 ____。
> 如果不用，我的兜底方案是 ____（质量/效率差异：____）。
> 要调用吗？（也可以回复"以后这类直接用"）

用户**点名要某类交付物**（"做成 PPT""画个架构图"）＝已授权该交付物；此时只有当环境里存在**多个同类候选技能**需要选型时才再问一句，否则直接选最匹配的并说明。

### 3. 获准——授权分两级

| 级别 | 含义 | 记录方式 |
|---|---|---|
| 单次授权 | 只覆盖本次任务的这一次调用 | 写进任务计划/交付报告 |
| 常备授权 | 用户说"以后这类直接用/不用每次问" | 追加到项目 `docs/jiangzuo/learnings.md`：`授权：<情境> → 直接调用 <技能/技能类型>`，并提醒用户该记录已生效 |

- 授权范围**只有用户能给**。禁止自行"推断默认授权"、禁止把常备授权扩大到未授权情境（授权了"图表技能"不等于授权了"图像生成"）。
- learnings 里的授权记录在任务开始时先读一遍，等于快速恢复授权状态。

### 4. 调用——交接单要完整

把分包商当新来的外包团队，一次交代清楚，不让对方猜：

- **目标**：这个活最终为任务的哪条验收标准服务
- **上下文**：相关文件路径、项目约束、风格要求、已有结论
- **期望产出**：格式、落盘路径、命名
- **验收标准**：怎么算合格（可检查的条款）
- **禁区**：不许动什么、不许联网/不许改配置等限制

### 5. 核验——交货要验收

- [ ] 产物真的存在、能打开（文件生成≠内容正确）
- [ ] 内容匹配需求：条款齐全、没有占位符和 lorem ipsum
- [ ] 数据准确：抽查关键数字与真实数据源一致（精确图表尤其要查）
- [ ] 风格一致：与项目现有产物/品牌不冲突
- [ ] 没越权：没有改动交接单禁区里的东西

不合格 → 带着**具体问题清单**退回重做，或切兜底方案。核验证据（跑了什么、看了什么）写进交付报告。

## 兜底策略（永远带着 B 计划提议）

| 情况 | 动作 |
|---|---|
| 环境里没有对应技能 | 直接走兜底方案，不打断用户；交付报告中注明"如安装 X 技能可提升 Y" |
| 用户不同意 | 走兜底，不重复推销 |
| 调用执行失败/产出不合格 | 退回一次；仍不合格切兜底，不要死磕 |
| 拿不准该不该提 | 不提，用手头方法完成——宁可少编排，不可停摆任务 |

## 成功 / 失败示例

**好的协同**：
> 用户："功能做完了，帮我给团队讲讲。"
> → 盘点：环境有演示文稿技能。→ 提议（按话术，含兜底"Markdown 大纲"）。→ 用户："行"。→ 交接单：目标 15 页内讲清架构与演示流程；上下文附 architecture 图与接口契约路径；验收：能打开、无占位符、截图来自真实页面。→ 产出核验发现第 8 页数据与实际 API 响应不一致 → 附具体问题退回 → 修订版核验通过 → 交付报告注明"演示文稿由 pptx 技能产出，经一轮核验修订"。

**失败的协同**：
> 用户："帮我做个图表。"
> → 直接调了图像生成技能，画了张漂亮但数据随手编的装饰图。
> 教训：先分清交付物是"示意图"还是"精确数据图表"——前者可用图像生成，后者必须用图表技能或代码绘制，选错类型返工又失信。

## 常见错误

- 未获准就调用——哪怕你百分之百确定用户会同意。
- 凭技能名字猜能力，交接单空空如也，让对方自由发挥。
- 调用后当甩手掌柜，把分包商输出直接当已验证成果交付。
- 一次提议一堆技能轰炸用户。
- 对方技能不可用时把任务卡死——提议里永远带兜底。
- 把一次授权当成永久授权，或把 A 类授权扩大到 B 类。
