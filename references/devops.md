# 分册：部署、环境与 CI/CD

> **何时读**：配置环境、写部署脚本/容器、搭 CI、发布新版本、用户报"我本地跑不起来"时。
> **前置**：知道项目的运行方式（onboarding.md）。
> **产出**：可复现的环境、可回滚的发布、有告警的线上服务。

## 环境配置

- **12-Factor 原则**：配置与代码分离——一切环境差异（数据库地址、密钥、开关）走环境变量，代码里只有默认开发值或报错提示。
- 维护 `.env.example`：**每新增一个环境变量必须同步更新**，含说明（给谁的、格式、去哪拿值）。"跑不起来"类问题的头号根因就是 example 落后于代码。
- 环境分层：dev / test / staging（有条件就上）/ prod；staging 尽量像 prod。
- 密钥管理：不进代码、不进 git、不进镜像、不打进 CI 日志（security.md）。用户报"跑不起来"时，先对着 `.env.example` 和 README 快速启动段核对缺了什么。

## 容器化（项目需要时）

- Dockerfile 要点：多阶段构建控体积；`.dockerignore` 排除 `.git`、`node_modules`；用固定版本基础镜像 tag（不用 `latest`）；容器内非 root 运行；声明 `HEALTHCHECK`。
- docker-compose 用于本地一键起依赖（db/cache/queue），版本号固定。
- 构建产物可复现：锁文件（lockfile）必须参与构建。

## CI（有代码托管平台就用）

最小流水线，PR 必须过：

```
install → lint → test → build
```

- 失败即阻塞合入；测试不过不合并是纪律不是偏好。
- 缓存依赖加速（按 lockfile 哈希做缓存键）。
- 本技能自带校验可加进流水线：`python scripts/validate_skill.py .`（本仓库的 CI 已示范）。

## 发布

- **没有回滚方案就不发布**。发布前先回答："出问题怎么退回上一版？需要多久？"
- 用 templates/release-checklist.md 逐项过：版本号、CHANGELOG、迁移顺序（先兼容后删）、灰度计划、回滚命令、值班通知。
- 数据库迁移与代码发布的顺序：加字段/加表先行（旧代码兼容）→ 发新代码 → 删旧字段单独一批。**禁止**在同一发版里又删列又上线依赖它的新代码。
- 发布后盯 15-30 分钟：错误率、延迟、核心探活；有异常走 incident.md。
- 版本纪律：语义化版本（破坏性升 major、功能升 minor、修复升 patch），tag 与 CHANGELOG 同步。

## 可观测性（上线的东西必须看得见）

- 日志：结构化（JSON 更佳）、带请求/链路 id、落到文件或日志服务而不是只打印控制台。
- 指标：至少覆盖 QPS、错误率、延迟 P95、资源占用（CPU/内存/磁盘）。
- 告警：错误率和延迟设阈值，**告警必须有人响应**——没人看的告警比没有更糟（狼来了效应）。
- 探活：健康检查端点区分 liveness（进程活着）和 readiness（依赖就绪）。

## 备份与密钥轮换

- **备份**：有备份策略还不够——**恢复演练过才算有备份**。定期在隔离环境用备份真实恢复一次，记录耗时与坑。
- **密钥轮换**：人员变动、疑似泄露、外包结束时立即轮换；轮换步骤写进部署文档（谁有权限改哪里、改完要重启/重发什么），不要等出事现场研究。

## 检查清单

- [ ] 新环境变量已更新 .env.example
- [ ] 密钥只存在于环境/密钥服务，未进代码与镜像
- [ ] 构建本地跑通过，镜像能起、健康检查通过
- [ ] CI 流水线全绿，失败会阻塞合并
- [ ] 发布检查单过完，回滚命令演练过（或明确写出）
- [ ] 迁移与发版顺序确认无兼容窗口问题
- [ ] 发布后观察期指标正常
- [ ] 部署文档已更新（docs-delivery.md）

## 常见错误

- 代码在开发者机器上能跑、换台机器跑不起——配置散落在各处没进环境变量。
- 镜像里打包了 `.env`（密钥随镜像分发）。
- CI 里的密钥用明文写进 yml 而不是平台的 secrets。
- 没有回滚方案的发布，出事后现场手忙脚乱。
- "偶尔超时"没有告警，三个月后才知道磁盘早就满了。
