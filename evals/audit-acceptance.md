## 这一轮量出来的四个真缺陷（全部有红/绿配对）

1. **库与应用不分**：requests 是纯库，却被 `scope: app` 的配置型规则（调试开关、会话 cookie、
   错误信息回显）报了 8 条。修法：`repo_role()` 判角色 + 规则 `scope: "app"`，
   `requests` 走 library 档。**反面教训先记着**：角色判定最初用"没有路由就当库"，
   把过程式 PHP 的 DVWA 判成库，**压掉了 7 条真漏洞**——现在要求"有打包清单且
   docs/examples 外没有真实页面文件"才算库。
2. **字符串字面量里的单词被当成变量读取**：DVWA `impossible.php` 报反射 XSS，链路是
   `$id = $_GET['id']` → `$db->prepare('… WHERE id = (:id)')`——占位符名 `:id` 撞上了
   变量名 `id`。修法是 `carriers_of()`：按语言剥字符串，只认显式内插语法
   （PHP 双引号 `$var`、Ruby `#{var}`、JS 模板 `${var}`、Python f-string `{expr}`）。
3. **守卫条件被当成数据入口**：`if ( isset( $_POST['Submit'] ) )` 只出现过 source、
   没有赋值目标，就走 `__inline__` 兜底，于是同函数里任何 sink 行都认领这条流——
   DVWA 每个模块开头都有这句。修法：`__inline__` 只在**与 sink 同一行**时成立
   （`os.system("ls " + request.args['d'])` 这种真内联仍报）。
   **连带量出的第二个缺陷**：收紧后 DVWA exec 的 8 条命令注入**全部消失**——
   原来那 8 条是靠守卫误报**误打误撞**报出来的，真正的洞在 `$_REQUEST['ip']`，
   而 CMDI-001 的 source 只写了 `\$_(?:GET|POST)`。补齐 `$_REQUEST`/`$_COOKIE` 后回到 6 条，
   且 impossible 档这次是被净化拦住、不是靠误报撑住。
4. **过程式 PHP 的页面入口没进可达根**：DVWA 的漏洞体在 `vulnerabilities/*/source/*.php`，
   由 `index.php` 用**变量路径 + 无括号** `require_once DVWA_WEB_PAGE_TO_ROOT . "…/{$vulnerabilityFile}"`
   引入，静态图跟不动，于是招牌漏洞被标成"不可利用"降档。修法：PHP 模块级出现变量读写
   就把该文件当页面入口（纯 `class`/`namespace`/`use`/属性声明的文件不算，
   `tests|examples|docs|vendor` 路径不算）。DVWA 的"不可利用"标注全程是
   **12（v0.29 基线）→ 40（加规则后）→ 18（缺陷 3 收紧守卫）→ 0（这一条）**。
   其中 65 条那一阶段的 JSON 已按卫生约定删除，数字取自当轮真实输出；
   **18 与 0 两档的 JSON 仍在运行区可复查**（`eval-runs/tp6-dvwa.json`、
   `eval-runs/tpf-dvwa.json`），12 与 40 两档要复现需 checkout `v0.29.0` 重跑同一命令。

## 检出分母：DVWA 按模块主类别算只有 7/19（v0.33.0 补到 10/19）

前面所有百分比的分母都是我自己的语料。DVWA 不一样：**模块目录名就是标准答案**。
`evals/audit-fixtures/dvwa_coverage.py` 把扫描结果按"模块 → 该模块的主漏洞类别"对照，
口径写死在脚本里：**只有该模块的主类别规则命中才算 OK，"同目录路过报了别的种类"不算**；
只在官方修复档 `impossible.*` 命中也不算。

| 版本 | 主类别检出 | 说明 |
|---|---|---|
| v0.32（补规则前） | **7/19 = 36.8%** | api / csp / exec / sqli / sqli_blind / upload / xss_d |
| v0.33（补 sink/规则） | **10/19 = 52.6%** | 新增 xss_r、open_redirect、weak_id |
| v0.34（跨文件模块池） | **11/19 = 57.9%** | 再补 fi（A/B：只新增 2 条、一条没消失） |

补的四条都是"写法没认全"，不是"类别没规则"：

- **PHP 输出缓冲拼接**（xss_r）：DVWA 的反射 XSS 是 `$html .= '<pre>Hello ' . $_GET['name'] . '</pre>'`，
  `echo` 在模板里。新 sink 要求**同一行内联读外部输入**且后面出现 `<tag`，
  窗口写死 `{0,300}`（见下面的复杂度事故）。
- **无括号的 `include $file`**（fi 的半条路）：原 sink 写成 `(?:include|require)_?once?\s*\(`，
  而 `once?` 意为"必须有 onc"，所以**不带 `_once` 的 include 永远匹配不上**——
  这是写在规则里的正则错误，不是设计取舍。
- **小写 `location:`**（open_redirect）：DVWA 用 `header ("location: " . $_GET['redirect'])`，
  原 sink 只认大写 `Location`。

  计数器自增当会话值、`time()` 当 cookie 值、`md5(计数器)`；

## 一次复杂度事故（时限锁为什么必须有）

补 sink 时我写出过一条 `[^;]*(?:A[^;]*<|<[^;]*A)` 的正则：**失配时每起点重扫，O(n²)**。
实测同一条模式在 600KB 行上要跑 **106.7 秒**；真实扫描路径把单行截到 4096 字节，
所以本地与 CI 都"看起来没事"——这正是记忆里那条"本地跑得快不是复杂度证据"的复发。

- 第一次改法（把锚点前置、只留一个 `[^;]*`）**没治好**：把 superglobal 锚点铺满整行时
  仍要 10.4 秒。**说明"一条防线只测一种形状"不够**——这次是第二条形状（锚点 Everywhere）
  把它逼出来的。
- 最终改法：`\$_(?:GET|POST|REQUEST|COOKIE|FILES)\s*\[[^\]]*\][^;]{0,300}<[a-zA-Z/!]`
  ——窗口有硬上界。540KB 对抗行从 10396 ms 降到 **15.3 ms**，DVWA 真实写法仍命中。
- 同一个锁还顺手抓到一条**早就存在**的无界写法：`JZ-SECRET-001.unless_present` 的 `<[^>]+>`
  （600KB 行 6.2 秒），也 bound 成 `{1,200}`。这条不是我本轮引入的，是存量缺陷。
- 新增 `TestAuditPatternCost`：对**每条规则的每个 pattern**（sinks/sources/sanitizers/unless_present）
  喂两条 200K 字符的对抗行（故意不放分号，让 `[^;]*` 一路扫到尾），单条限时 500 ms。
  还原后最慢 18.8 ms。牙齿已验证：把任一 pattern 放开成无界写法，当场红（8 处锁全红，
  其中"窗口放开成双无界"那处是靠 90 秒 timeout 拦住的——它根本跑不完，这同样是要拦的形态）。
- **对抗尺寸为什么是 200K 而不是 540K**：Python 中断不了一次正在跑的 regex 搜索，
  540K 上的二次方要 10 秒以上，那会让这条锁的表现从"报错"变成"挂死"，
  而挂死的 CI 不会告诉你是哪条规则。尺寸要选到"真有问题也只是几秒就红"。
- 校准流水线这一轮出过**第三次事故**：变异跑到一半被打断，仓库被留在变异态
  （`injection.json` 少了窗口上界），靠脚本收尾"逐字节核对已还原"才发现并恢复。
  现版 mutate/run/restore 全在 try/finally 内、子进程带 timeout、结束做字节比对。
  纪律：**注入/变异工具的失败路径必须自带还原证明**，不能假设自己会跑完。

**根因**：`analyze_function` 的赋值传播只看"等号右边有没有脏变量"，**完全不区分这个变量是实参还是返回值**。
DVWA 真代码（`vulnerabilities/cryptography/source/token_library_high.php`）里的 `check_token` 返回的**全是常量**
（`$ret` 的每个字段都来自常量表 `$users`；形参 `$data` 只用来解密校验和取下标，不进返回值）⇒ 那是误报。

**修法**：给每个 (函数, 规则) 算一份「**返回摘要**」——
`dep_pos`（返回值依赖哪些**形参下标**，如 `return $k;` ⇒ 依赖第 0 个形参）
＋ `own`（返回值**自带**哪些污点，如 `return $_GET[$k];`）。
摘要**按规则隔离**（`intval` 对 SQL 注入是净化、对别的规则不是），用**不动点迭代**求解
（被调函数的摘要要查别的函数的摘要）。调用方在赋值时不再把实参直接当返回值；
**外部函数**（不在仓库里的，如 `strtoupper`）保持原语义（保守，不制造漏报）。

## v0.53.0 E19（PHP 成员方法 `->method(` 不该借用同名仓库函数的摘要）
