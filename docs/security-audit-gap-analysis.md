## 五、诚实边界（写在这里，免得报告里美化）

1. **没有 AST，只有正则**。纯标准库意味着不能引 tree-sitter/ast-grep。调用图与污点链是
   **确定性的启发式**：Python/JS/TS 档（函数边界+参数传播）能给逐跳数据流；Java/PHP/Go 档先只保证
   sink 定位与文件级可达。每条发现会带 `analysis_depth` 字段说明它属于哪一档，不假装精度。
2. **"高危检出率 ≥90%、误报率 ≤10%" 的分母来自自建夹具**（`evals/audit-fixtures/gen.py` 生成多语言
   已知漏洞 + 诱饵，D 盘 `eval-runs/audit-bench/`，不进公开仓库）。夹具是自证的必要条件，不是充分条件；
   真实仓库只作为误报抽样，抽样口径（查了多少条、谁判的）会写进验收记录。
3. **工具不会让 agent 变成安全专家**。清单里第 7 项的存在理由恰恰是：LLM 报漏洞会编造文件行号。
   新链把"报之前先核验"变成机器步骤，但业务逻辑漏洞（越权、竞态、支付）仍要靠
   `security.md` 的问句与 `code-review.md` 的自疑循环，规则引擎覆盖不到。
4. 修复建议**只输出文本**，全程不改源码——与"最小改动/同意≠扩大范围"（`SKILL.md:141`）一致。
